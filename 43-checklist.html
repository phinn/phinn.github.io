The 43-App Survival Checklist

I shipped 43 apps in one month. Apple flagged 27 inside 14 days, struck the account twice with 4.3, and froze 6 apps. These are the 77 checks I now run before every single submission — so you never learn them the way I did.

A. Portfolio & Listing Layer (12 checks) — where 4.3 / 4.2.6 lives

  1. 1New apps in rolling 14 days ≤ 5?
  2. 2New apps in rolling 30 days ≤ 8? (extended budget for slow-burn accounts)
  3. 3Any two app titles share a rhyme suffix or template word?
  4. 4App name free of another company's trademark?
  5. 5Subtitle free of another company's trademark?
  6. 6Keywords field free of competitor trademarks? (legal risk + review flag)
  7. 7Support URL live, loads <3s, no template clones of sibling apps?
  8. 8Support page has per-app unique h1 + section order?
  9. 9Privacy policy URL live, per-app, names the app specifically?
  10. 10Marketing cadence not identical-day across apps?
  11. 11Screenshots don't share identical framing across portfolio?
  12. 12Category + age rating consistent with actual feature set? (4.3(c) bait)

B. Binary & Metadata (14 checks)

  1. 13Build number never used on ANY platform of this app?
  2. 14Version string matches intended submission, no placeholder?
  3. 15No debug flags, test menu, or hidden admin panels reachable in release build?
  4. 16Third-party SDKs all updated (no deprecated API warnings in archive)?
  5. 17Info.plist purpose strings present and specific (camera / mic / location)?
  6. 18No private API calls (verify with otool grep, not trust)?
  7. 19App icon correct sizes, no alpha channel?
  8. 20Launch screen matches final UI layout?
  9. 21All localized .strings files present for claimed locales?
  10. 22No hardcoded strings visible in UI for claimed locales?
  11. 23Demo account credentials work if login-gated?
  12. 24Sign in with Apple offered if any third-party login exists?
  13. 25No payment references to external methods in binary metadata?
  14. 26URL schemes registered and tested?

C. In-App Purchase & Payments (11 checks)

  1. 27All IAP products in "Ready to Submit" with localized metadata?
  2. 28IAP screenshot uploaded for each product?
  3. 29Purchase restore mechanism implemented and tested?
  4. 30No mention of external payment methods anywhere in UI?
  5. 31Subscription terms (length/price/renewal) visible BEFORE purchase?
  6. 32Subscription EULA + privacy link inside paywall?
  7. 33Free-trial auto-renew disclosure explicit?
  8. 34Price tier consistent across locales?
  9. 35Server-side receipt validation implemented?
  10. 36Consumable purchases re-purchasable after restore?
  11. 37Family Sharing decision made (on or off) and consistent?

D. Review Notes & Demo Flow (10 checks)

  1. 38Review notes explain EVERY non-obvious feature?
  2. 39Demo account credentials current and tested THIS week?
  3. 40Hardware-dependent features have video demo link in notes?
  4. 41Review notes mention data reset procedure for reviewers?
  5. 42No "test" language left in notes from previous submission?
  6. 43Contact person reachable during review window?
  7. 44Phased release setting intentional?
  8. 45Copyright year updated?
  9. 46License agreements attached if using third-party assets?
  10. 47Review notes preempt known rejection patterns?

E. Screenshots & Marketing (10 checks)

  1. 48Screenshots show real UI (no mockups that diverge from app)?
  2. 49No device frames that Apple considers misleading?
  3. 50Text overlays don't promise features not in the build?
  4. 51Screenshots match current app version's UI?
  5. 52All required device sizes uploaded?
  6. 53App Preview videos (if any) show the actual app?
  7. 54Promo text within limits, no price references?
  8. 55Description matches actual features (no vaporware)?
  9. 56What's New section written for this version?
  10. 57Screenshots color-space sRGB (P3 can shift) and text legible?

F. Post-Submission Discipline (12 checks)

  1. 58Submission logged with date, app, build, notes?
  2. 59Account-level submission velocity tracked weekly?
  3. 604.3 / 4.2.6 strike history documented per account?
  4. 61Rejection templates pre-written for likely rejections?
  5. 62Response SLA: reply to rejection within 24h?
  6. 63Escalation path defined (App Review Board → dev support)?
  7. 64Apology-free factual reply style (no begging)?
  8. 65Each rejection answer is per-question structured (Q1...Q9 format)?
  9. 66No mass-appeal template replies across apps?
  10. 67Post-recovery cooling period respected before next batch?
  11. 68Binary cache purge confirmed before resubmission?
  12. 69Retention policy: keep all correspondence for 12 months?

G. Personal-Data & Compliance (8 checks)

  1. 70Privacy nutrition labels match actual data collection?
  2. 71Account deletion path exists if account creation exists?
  3. 72Data collection disclosed in-app before it happens?
  4. 73Analytics SDKs documented in privacy labels?
  5. 74COPPA compliance if kids category?
  6. 75GDPR data export/deletion tested?
  7. 76China-specific: ICP filing number displayed if required?
  8. 77Export compliance (encryption) keys answered correctly?
